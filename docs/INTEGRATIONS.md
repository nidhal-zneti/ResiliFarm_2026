ResiliFarm does not depend on IoT devices. Open-Meteo provides live regional and saved farm-coordinate weather-model data, plus soil moisture and temperature model variables displayed in the Digital Twin. These are model outputs, not farm or station measurements. ISRIC currently reports its SoilGrids REST service paused; no soil survey connector is active. Farm-specific flow, pressure, boundaries, pump-energy and solar-generation feeds remain unintegrated. The app does not present those values as live. Generated farm/network/simulation records are removed at initialization; calculation outputs require user-entered farm parameters and are labeled estimates. The backend owns Open-Meteo requests; frontend code does not call the provider directly. Successful responses use a process-local five-minute cache.

## Pretrained Studio model (2026-11-21)

The optional Studio provider is now integrated with **Qwen3 4B Instruct**, served by a workspace-local **Ollama 0.40.17** runtime on `127.0.0.1:11434`. The Windows archive was downloaded from the official Ollama GitHub release and verified against its published SHA-256 (`3dd80f6e3a9699f2eadf4ac418f00529cee594df9557541806eda1f1f3f5588a`). Model weights are downloaded by Ollama and checked by its manifest/digest verification, under `.local/models`; they are not committed to source control.

[Qwen3 4B Instruct](https://ollama.com/library/qwen3:4b-instruct) is pretrained and distributed under Apache-2.0. Preserve its license/notices when redistributing weights. [Ollama](https://github.com/ollama/ollama) is the runtime; retain its applicable distribution and third-party notices. The design planner sends the original Studio request, typed current options and planning preferences to the configured model. Agriculture answers also send retrieved source passages to that model. With the supplied launcher, model inference stays on localhost; Tavily receives the question and selected region for retrieval. A separately configured remote model provider would receive its prompts.

The design planner selects a validated set of catalogue options through JSON-schema output. That planning path does not generate executable firmware, arbitrary components or reviewed wiring. Local code still constructs parts/connections and performs compatibility checks. Failed or malformed AI output produces an explicit error without persistence, not a silent rule fallback. It is not a trained agricultural prediction or anomaly-detection model. Water, energy, stress and telemetry workflows continue to use their documented formulas/rules.

The separate **Generate code** action sends the current pin map, farm context, selected relay polarity/sensor, hardware notes and control requirements to the configured model. Qwen writes constrained Arduino irrigation decision logic; local code assembles the complete ESP32 sketch with sensor drivers and actuator scheduling. Local Ollama uses `/api/chat`; other configured providers use `/chat/completions`. Compilation uses the workspace Arduino CLI and Espressif board core when configured, before saving a new version. The manifest records model, source version, GPIOs and actual compilation status. Outputs remain disabled by default and no hardware is flashed. Code generation is not a field-validation or safety certification; see README for calibration and hardware limits.

Real-model verification passed EN/FR/JA solar-without-Wi-Fi planning, one-sensor contextual edits, solar removal with LoRa preserved, unsupported requests without persistence and Japanese ZIP export. On this RTX 3060 Laptop GPU (6 GB), the first EN request took 10.19 seconds; subsequent FR/JA creation took 3.99/3.56 seconds. These are local smoke-test timings, not accuracy or performance guarantees. See README and `scripts/verify_studio_ai.py` to reproduce. The earlier repository evaluation above remains historical; no weights from those ten candidate repositories were imported.

## Library attribution

Runtime libraries are installed through package managers, not copied source trees. React/Vite/i18next/Recharts and most UI tooling use MIT; Leaflet is BSD-2-Clause; Lucide uses ISC. FastAPI/Pydantic/SQLAlchemy/HTTPX use MIT; Uvicorn uses BSD-3-Clause; Psycopg uses LGPL-3.0 (retain installed distribution notices). PostgreSQL has the PostgreSQL license. Preserve package license files when redistributing containers/bundles. Google Fonts are optional font requests with system-font fallback; no downloaded font files are bundled.

## Verification limits

No WNTR, pvlib, DiTEC-trained model, NASA/FAO portal or proprietary engineering API is integrated. The simplified implementations are deliberately independent and their assumptions appear in the UI and README. No benchmark accuracy or validated field performance is claimed. PostgreSQL DDL compiles, but Docker/PostgreSQL execution was unavailable locally; SQLite is the tested persistence runtime.

## Fruit ripeness

The former Cybersecurity navigation section now provides a single-photo Fruit Ripeness flow based on the FruitVision project's AB colour-and-shape classifier concept (upstream: [ligitpizza/FruitVision](https://github.com/ligitpizza/FruitVision)). ResiliFarm reuses its own FastAPI authentication and SQL database; it does not run FruitVision's separate Flask app or database. The API accepts JPEG, PNG and WebP uploads up to 10 MB, discards photo bytes after inference, and records only the user, predicted fruit/ripeness, confidence, recommendation, model version and timestamp. Users see their own history; administrators can see all results.

FruitVision does not publish trained ripeness weights. The referenced Kaggle dataset metadata identifies the source dataset as CC BY-SA 4.0 (creator `leftin`); the download and prepared apple/banana/orange images are local under ignored `.local/fruitvision/` and are not committed. Attribution and license are written to `.local/fruitvision/DATASET_ATTRIBUTION.txt` and into each model manifest. Five upstream AB preprocessing/feature modules are included under `backend/app/fruitvision_ab/` with per-file source links and a NOTICE; reuse was confirmed by the user. The model is the FruitVision Member 1 AB SVC over its actual color and contour-shape features. A held-out Kaggle test split is evaluated after the upstream single-fruit shape check; the manifest records held-out coverage, accuracy, and per-class report. The API enables only fruits with all three tested labels and uses no generated fallback. Keep the dataset and trained weight files local unless redistribution is confirmed under the dataset license.

## Supplier price access

Supplier domains are candidates only; price lookups are off by default. To enable a country, set STUDIO_SUPPLIER_DOMAINS_TN or STUDIO_SUPPLIER_DOMAINS_JP in the server environment to an exact candidate domain, and only after permission for retrieval and reuse is confirmed. The app accepts only curated domains and shows each comparable listing link. Listing amounts form planning ranges; explicit roll lengths can be converted to per-metre prices. A configured model may estimate missing prices from general knowledge, with a range and product assumption but no supplier attribution. Unknown quantities stay excluded from totals. Neither listing similarity nor model output establishes validated accuracy or engineering suitability. Hobbystart and Total Tunisia are candidate sources whose reuse terms have not been confirmed. Japan candidates stay disabled by default: [Sengoku terms](https://www.sengoku.co.jp/sales_contract.html) restrict copying, modification, distribution, sale and publication without prior written permission, while [MonotaRO terms](https://www.monotaro.com/main/rule/) prohibit copying, selling or publishing information obtained through its service.
